Decisions:
- One server secret, SIGNIN_SECRET (at least 32 characters), keys every stored hash; the code key and the address key are derived from it by HMAC-SHA-256 (RFC 2104) with a label each
- Codes are stored as HMAC-SHA-256 of "<email>\n<code>", drawn by rejection sampling over a uint32 from crypto.getRandomValues, compared in constant time; session tokens are 32 random bytes (hex), stored as SHA-256
- New stored data: migration 0001 adds tables accounts, codes, sessions, request_counters (times in ms; email CHECK lowercase); rolled back by dropping the four tables, which nothing else reads
- A new code is stored only after its email is sent, and in the same D1 batch supersedes every lower-id live code of that email from the same requesting address
- A wrong try takes a slot of the address's hourly counter before any code is looked at, and a right code gives its slot back
- The email box is a text box (inputmode=email), not type=email
- The sign-in steps both post to / and are told apart by a hidden step field; the code-entry step carries the email in a hidden field and links back to /
- The test switch's stand-ins (fake mailer record, clock offset, armed code-store fault) live in one module-scope object in src/worker, built only when VID_TEST=1
- wrangler.jsonc keeps a placeholder D1 database_id (all zeros); the real id is set by the deployer at the first hosted deploy
